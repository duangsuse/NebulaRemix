# 对鸿蒙工具链的误解

- OpenHarmony“鸿蒙”、ArkTS(包括MapleIR)、Cangjie，从这三年对华为的观察，这个大厂或许真有诚心，去做编程工具链？

没错。三年前我以为鸿蒙方舟这些和“满血摘星门把手” “纯血鸿蒙vs杂种哄懵” “半血友商”一样系噱头营销…… 今天看来，虽然仍缺乏独创性，局限于其【自主融合】的氛围，管理层却是投够了钱，也找对了团队与外援。

虽然和张洪波、胡渊鸣、易老六他们比，这些“一人团队”的灵感还差了火候，却胜在全面。[从此文可以看出]()团队并没有被编译原理或“学院派”的那些白象所蒙蔽，他们宠辱不惊，却又认真的换位思考，这点对中国科普诚为难得，这才是真正长远的技术力啊。 和打乒乓球一样一直靠“天才”怎么叫自主？

或许像Telegram那样力大砖飞是可行的。花钱就能够推进【技术基建】，并非只有JB和印度那些专业公司能做。 Google后来居上的Gemini又怎么不是如此呢？它本来就有算力有语料库，而华为，**也本来有能“训练”好一门新语言的大量App需求。**

- 在新框架上大胆默认定义式编程+H5风格，是明智的选择！

我们曾以为，深耕安卓的华为一定会被 Android/JavaEE 那套八股文给带歪，至少在咕狗家清醒者也是少数；现在看来 MVC,MVP,MVVM 里的一些文字游戏、好大喜功的办公室政治，没有干扰在ArkTS里写UIUX的“原生感”。

CTO的洞察力是在线的：**比 React 更正确，比 Vue2 模板更简单，比 Vue Compose 更类型化，这是非常难得的**，尤其在于它是大厂圈里的“白莲花” 而不是社区严选的扫地僧。.ets 比之前拆解的VanJS也只是差点灵感，没有了范式上的差距。

- _OHOS系列项目和生态，是否值得，接收我们数年闭关积攒下来的体系？_

我一直是反对“汉芯、红芯浏览器、中科院木兰、VSCode套壳自研”那样，在国内 IT/CS 界的【碍国抽象事件】的，虽然我对木兰这种“<u>py2to3的赝品</u>”提不起兴趣 我也还是关注了。

这种态度的内核却是，“彼可取而代之”，我是觉得 “咱们圈 值得更好的”。
虽然汉芯之流很糗，但对 龙芯(RISC5)、大疆、长江存储这些，包括TiKV、TPLink等民企，却千万不要只因“声名在外”而一棍子打死：自吹自擂和实至名归是不同的。

**我们不要从宏大叙事的角度考虑实际上的问题。** 输赢是为了技术，技术却不是为了输赢，倒果为因，打哪指哪，被侮辱的只是自己的智商。
如果真是为了科创的进步，身边中文圈的发展无疑是回馈最大的： 中国人很聪明，只是太限于“预制的聪明”，不寻求智慧；中国人也很勤奋，但往往是得不到自信的代偿，以至于不值得，无论阶层。 而结合鸿蒙栈这件事来讲，对中文博文和智慧的开发可以是有影响的。原神Rust凭一张嘴不就做到了？

如今，浏览器御三家都有了自己（亲生or钦点）的PL (`Google #Go-Kotlin, Moz://a#Rust-JS, Apple #Swift`)，连社区都有 py/php/lua/web3/GTK-Vala.. 
难道华为这一从3C到5G，从toC到toB都有业务的基建型老牌企业还不配吗？

从资本上考虑，华为投入的钱和勇气值得收获成果。 虽然鸿蒙之下的栈冷门到需要挽尊了，念其不破不立的精神和扎实的领域技能，或许，该有更广的应用。

- 那么它配“截收”了？

问题是这成果属于谁。 "HOLP"之下的元编程技术，命名权可以是某些公司的，只要它们能对等的为生态提供社区资源、衍生应用、公共关系、人才人脉上的加速。

但是，将【ohos核心生态】下的源码，尤其是员工主创的技术，用于其他开源项目时，<u>一定一定不能够被卡脖子，必须一直一直是Open产权给全世界的。</u> 就算不和Python的 "BDFL终身大统领" Guido或GNU家比，和咕狗开源的安卓酷容相比，在放权上也不能够更差！

作为国内少有的，愿意给编译原理和工具链的“重造轮子”投钱，而且确实祖传做基础设施的大厂，如果十年后就做出个“缝合怪”，市场上因此没有讨论度，未免可惜！
**我[不喜欢“百毒”]，但觉得贴吧设计得比Reddit好玩，多元化本身就是好事，它是未来的选票。**

这个领域机会很少。更不要谈那些不热爱工程却爱面子、爱摘果子的“研究者”们了，独善其身是爱惜羽毛的诅咒。 
国内今天有这样的土壤，就像过去的登月科技、像中秋节的烤肉一样，过了时节再等，可就晚了。
提到月亮🌙，我不太看好张洪波的Moonbit，他聪明勤奋却不如ohos务实，这样在YC和各种Hunt上好讲故事，却叫好不叫坐。

我们很清楚【自主可控】是没必要做到鸿蒙这个地步，那为什么不真正的，替全网的Devs向舒适区之外迈进呢？
为了我的长期项目，积攒这种试错经验对ohos也是好事，毕竟IT领域没有“放哪都对”的技巧，却有四海皆准的思想。

我也很想问自己，我一个数学不及格的大专生，凭什么在自己私定终身的领域“指点江山，教人做事”： 我并非清华肄业，也没上过北上广深的外国语学校，我更是从未在邮电浙大USTC的门口待过半载、喊过万岁。
未出国门对这个领域的专家是少见的。但，我默认自己是元编程天材，材料的材。

你也可以看到我的本质： **我，无需自认、或被公认为是天才，才能去参与我乐意去做的事**，无论这事业涉及什么专业。 感谢资本主义开源！

计算机的科学是什么？是工程的方式与其工具。 对它而言，没什么是天生的最优，连最佳实践，也虚掩着被“预制”好的语境和限制。
新的生态，需要的并非满分，而是【打破满分、重启规则】。

满分不是“天生才有”，它只是追求天道与真理的“材料”。这种对【原本】的执着和忘我，对应着编程语言们对各种技术栈和App的博爱之责：它不停，却不变，上善若水，水善利万物而不争。

**理论的未来从来就不是发现“天成”，而是开创人城。**
CS不是数学，它不愿畅谈“绝对”，也心存对“求无限值”的敬畏，因此…… 开枝散叶出DNN和CAD的才能是它。 比之数学为天，CS天人合一，比之数学为地，CS复土开疆；

如果人们天生擅长编程，工具链的发展，到能“节省按键”的汇编器就该止步了。 事实却是：[我们制造工具的同时](https://henry.codes/writing/a-website-to-destroy-all-websites/ )，工具也在塑造我们，它在把更多人变成“我们”…… 
天才真的存在吗？  从四千年前到如今，天才的比例和智慧，有定数吗？是和脑容量相关的？  给天才打分的，是天才吗？或是 <u>天然存在的难题</u> 吗？

各种意义上，天才是被工具塑造出来的。
有些人不擅长当“天才”，或者因身份条件而挤不进“天才”的流水线，他们只是挺身而出、著书立说的的凡人——但那又如何？  

**“高阶”的天才，是指擅长塑造天才的天才，也包括着能被工具塑造出的“天材”。 我学元编程，而我讲的，便是看得见摸得着的“社会元循环”。**

这段文学创作就是我从 PL/OS/Creative 编程领域学到技术的证明。 有时候，特别是对出众的PLT研究者，简单是终极的复杂。

我们被称为开发者。我开发的是别人的天材，而非天才的别人。
因为：我不信人间智慧自有天数！不破不立，希望，你也一样。
><u>🐎人写代码，其实是他不爱被代码写</u>，把握求知的工具，别被它把握了！—— [《知道规则者、创造规则者》](http://bilibili.com/bangumi/play/ep1489492)

- 那假如，你与同行合作的话，不会有问题吧？ 人有了能耐，脾气准格色。你的特质又是什么？

**我追求的编程，维度不是“能用”，而是 _能让人安心_。** 无论是在原型、升级、修复、兼容/移植/PoC时，我都不会让软件下游无缝插手、无法安眠。 我的底气在于[《学习的智慧》]() 与教给自己的 [《计算机科学课程》]()

许多“敏捷开发者”节省了小组的时间，似乎对需求对答如流，却在下个月带着整条河流，一层一层的返工，我总能预见到这些。 长期对【框架比较学】的认知告诉我：**所谓效率，一定是在 _清楚说出_ 主创想写什么领域或交互场景的情况下衡量。**

优雅的代码未必就正确，但“正确”的代码，一定短而不凡、长而不乱。 如果更正确的API需要时间的考验，我宁可用自己demo试错的时间，去换成百上千的下游，千千万万次调用的开发体验。
何其有幸？当你说的清何为【正确的代码】，它便总是高效的！人、机、检查器，都很开心。

我所有的脾气、我和下游的共情，是因为我碰过无数多次的壁，踩过多少夜晚的坑，最终得到的，却是 <u>一段话说的清的答案</u>？ 这种矛盾是对所谓编译原理的讽刺。 所以最终，我选择将自己的思维放进容器：我不许任何框架侵入我的【领域心智模型】，我写的代码好似对这模型的摘要、序列化形式、API桥接。

编程界最显而易见的盲点就是【自作聪明】。我很忌讳聪明的、高度抽象的，却并不泛用的代码。
架构师的高傲，在于把自己有限的智慧用在了刀刃上，而不是拿刀架子当作毕生所学。

很遗憾，缺乏科学精神的人懂的越多，就反而拿越珍贵的刀摆弄架子 ——知识的“代码”进了他们空壳的精神。而我，把握求知的理论，它们却限制不了我！

意图是知识的根系。早在学会【所有编程语言】前，也就是按 范式×语言特性(如LINQ"子语言") 而非字面结构学习编程之前，我早已明白，求知的原理在于获取 <u>第一手资料</u>，而且，在于牢牢抓住原作者的动机和创作环境。我无视掉囤积居奇的“IQ牛人”与内容农场的【信息呕吐物】，不要画蛇添足。 

自从我第一次对已完成的功能7遍推倒重来，不同语法或框架引入的杂音，再也干扰不了我的心中的语意：

**抓住动态，洞见动机，学会直觉**，而不是“new”到了知识的“指针”或“套接字”就一考定学习。 “new”的其实是噪音，心智模型才是真的信息，而“旧模式”的心智负担……是更重要的信息。
**动机是知识的根系，创作是掌握的象征；当莫扎特落笔时，作品已经铸成。** 没错，代码如诗，真正的诗会浸染你的思想，而不是你疲劳的眼睛。

# Talk,Code, both cheap

- 所以，也别那么严肃嘛！分享下你的近况吧，我懒得知道你学过什么，近况就行。

嗯，但不能忘那三个要求。
最上面我引用了一位学界同好谈 < infer T> 的文章，这在Kt和Java11上是很赞的特性，也适合辅助AI做检查。

比如 `<infer T> for fn(u:T):Pair<T,T>` ，这个参数签名用C调用的直觉也能看懂(T=>new Pair(T,T) eg. T:int)，好像它只是编译期计算的文字游戏

但是结合从fn内部推理 `return (u to u);  where: fun A.to(:B):Pair<A,B>` 给出(fn.rettype) 而无需写明T和T时，就需要真正理解类型变量这类反流控的“多点等值/应后值(inHole)”了，这是Java甚至C++的人很少用到的，类似地址复用导致“等位值”，JS Signal变量

其实到这层，依然是能用 `类型时==运行时.replace('for|if|def','run once')` 来理解，即 `fn.rettype=(x,)=>(T.v=x.type, [T,T, Pair].clone)` (此数组是在解析时创建，模板实化时汇总而填)
但是到了 `<infer T, infer R> for each(a: [T List], op: [T R Fun1]): [R List]` 这里，无论是否要推出RList，只知a 推op.T，或是T推a，或是在concat([Int List], it)的R位置推a=emptyList的类型？

总之情况还蛮多的。我能说的就是kt真兼容的工况不多，但不影响DX。 会用Haskell的guard模式匹配，不代表就无师自通了“把变量作为值”

- 哈哈，“应后值”？这就是你接下来想谈的一大概念吧？

好眼力，但别急！很多人并没有真的把interface{}这些“静态结构”当成json去处理过，这些属于lang.reflect和compilers的交叉领域，本身也值得我们去反思，自己对PL的practical理解。 

有些东西，就是像从只会执行MC那种(`/命令 参数组 全局变量; ..`) 代码，到会读取parse“多态”字面与调用链，到递归下降，再加上算术甚至缩进解析算法，然后才明白，中间卡脖子的其实都是非常非常小的技巧。

[下面Eval的定义](#怎样写一个解释器) 告诉你，在【所有编程语言里可用】的是，字面值、相对值(globals.'print',它就是"()"操作的参数0)、等位值(栏目答,let=等)、可选值(if-or,??)，以及json和 (a=>()=>(a))('括需') 等组合字面值

**再说一遍，无论多么糅杂，字面值、相对值、等位值、可选值、组合字面值**，关于它们的“语法函数”(比如 `"()"`)是绝对的基础，有它们在这就能写不少的算法，哪怕是“很复杂”的qsort。 多点等值的实现(无论“动态静态”)是解释器的象征，等位值的特征是可以随便重命名(API无关性)。有些组合类型无法持久化，但它们可被Map.get id“序列化”，所以PLT不适合教条主义者

当然，我在这里认真来讲这些，不代表我觉得 type inference 应该是很难写的函数，eat(s) parser 也一样，它们都是整个IDE的第0步而已。 
以上，同样不是“OOP静态”或“鸭子”类型系统以及PEG的一切，只是这个case很有趣，很高兴这位大佬罕文分享。

# 怎样写一个解释器

问你： `[= inc (>(x) x+1)]; (inc 0)` 的值是什么？

`Eval=env=>(e)=>{e=e.substr? env[e]:e; vm.push(e.call? e(vm.pop(),vm.pop()) : e.push? 函数apply(...e) : e是字面值)}`

函数apply(argK, ...stmt) 在env新加键，如 `argK.forEach((k,i)=> env1[k]=vm[-(1+i)]); stmt.forEach(Eval({['x']:vm[-1], ...env})); 清理栈参数; OK(vm.at(-1))`
如此 (x=>x+1) 的x就算双向绑定到(eval过的) vm[-1] 了！ 而且script全局=函数级/Let块

对，RPN就不教了。那这个Map.get的层叠copy式进入退出，明显有 `[[Str Any KV] List], [Str [Any List] KV]` 两种优化（前者一般是用“原型链”规范实现）。总比无论有无arg都要花内存好，而实际上，在初次let时新弄个KV来保留被遮盖的变量，对(AST.Apply)调用的eval返回时还原即可（CoW懒计算）。 是不是很有趣？

更实用的是，针对全局变量能编号化避免冲突(import隔离)。 `makes env: [Int Any KV]` ，yin 一直在说的就是这个：parser所得到的结果里，就不该有变量名 "x"！

在所有语言里，都存在三层次定义： I导入复用、II变量分块、III表达操作。 

如果开启(I) def inline，并且将(II)块内操作局限于可repr(不含指针句柄等RPC临时值)的类型，返回的表达式就会变成一种跨端跨期的数据，如同 `f"{字符串}{内插}"`

在特定的forif路径内，产生的程序表式同理。 Rust称其 `#[proc_macro]`，扩充了上一条的Clike宏。虽然它对纯函数“卫生性”的设计也很有问题就是了。 我写 TkGUI codegen 时根本没听说过变量名会冲突的概念，你猜我是怎么理解宏的(Ctrl+F 电路)…… 提示：我使用的宏叫[馈硬Quines]。馈赠、硬编码的第一个字。

含有漏洞的“值”这个说法新颖，我说出口你就懂了。 class Builder{} 甚至普通的构造器，都是有漏洞("应后值")的值！ 它和零依赖的JSON当然是不可比的，然而，没有它就无“编程”。 **还记得吗？要 _组合_ 了化繁为简、微言宏义，编程才能做到数学做不到的事情**

我说"应后值"，并不是在[提醒你~](#怎样写一个解释器)栏目答或匹配解构 `(左边项)=>` 的本质。hole值可以在[]或{}里。比如 `(B=>[1,B]) vs Fn((B,), [1,B])` 的语意就像镜子与reflect一样，可只有对后者，明显能知道(fn.rettype)的长度，甚至是a[0]的类型，也就可以生成 `if(a[0]==1)B=a[1]` 。 注意：这里面是没所谓魔法的，因为 x=1, 1=x 的左右本就可以交换啊！！ `(x)=> 为什么就不能是 <=(x)` ？

如果你觉得，含有未知数的“一堆”调用或树状调用，就不是值，甚至不是对象树了，那你完全可能写出批量产生SQL/CSS注入的框架，因为调用SELECT语句必须，或者说【迟早要能】创建这种函数值，或者用长到夸张的XML。 不爱较真，你甚至可能会为熟练 `for(u of users)if(u.age<18){return u}` 的十几个变体而陶醉，而这些关键词不过是C/CPU提供的一些汇编胶水，万年不变。

如果你明悟，就不用再依赖于各种gRPC或bindgen，甚至会忘掉React；你自己就能通过语言提供的钩子函数/operator override，创造量体裁衣的它们。 你还能理解操作系统对你的C调用栈干了什么，哪怕它涉及syscall/CFS队列这些无关的知识。

含有未知数的东西一般只存活于内存里，一旦要保活，它们就变成订单ID或 await WebHook 这种业务逻辑了，而在曾经，回调链表的地狱里也有它无处不在的身影。 因为异步栈和栏目答的存在，栈式内存管理(free-\n-return)的光辉都不再了，Rust的线性管理成了新的算法，不再是如同链表般单向。

对于应后值的研究绝对不新，但await和模式匹配时解构就是成果之一，那个[回应式编程Reactive]不知道自己是。 想想吧，自08年比特币后，有多少语言特性算得上病毒式传播？

哦，是时候介绍HOLP了。 Human Oriented logical-var-Lists Polyfill ，或许，这就是OOP+FP外的最后一种实用性编程范式。它启发于 SWI-Prolog, MiniKanren.org ，却又完全不类似，反而像pyjs与Excel的混血。

元编程，其实也只是编程。 用新代码来优化旧代码，是种魔法，并且存在怪诞的黑魔法和善良的白魔法。 
跟我一道，我会告诉你酷酷的黑魔法坏在哪，而软件工程里，又有多少白魔法在AI时代也能发挥巨大的作用。
